# QuickCookies v1.1 预览覆盖与流程可靠性规格

日期：2026-06-08
状态：草案，等待确认

## 目标

v1.1 的核心目标是：

`让 QuickCookies 成为 Quick Look 看不了或看不舒服时，最快、最轻、最可靠的临时预览工作台。`

这一阶段不追求把 QuickCookies 做成深度编辑器，也不追求为了显得全面而堆格式。v1.1 要解决的是一个更清晰的问题：

`用户在 Finder 里临时想看一个文件时，QuickCookies 能不能比系统默认方案更容易打开、更容易看懂、更容易退出。`

## 产品原则

1. 预览优先

新增类型默认只做预览、元数据、复制和外部打开。只有文本类内容才继续保留微编辑能力。

2. 流程优先

打开、切换、关闭、焦点回归和失败兜底，是 v1.1 的核心体验，不是实现细节。

3. 边界清晰

扩展更多类型是为了补 Quick Look 的临时查看缺口，不是为了进入项目级、编辑器级或平台级能力。

4. 可验证

每一种新增类型都要能回答：它解决了什么临时查看问题，用户为什么不应该直接打开完整应用。

| SQLite / 数据库文件 | 是 | 是 | 是 | 是 | 否 | 否 | 是 | v1.1 候选 |
| EPUB / 电子书 | 是 | 是 | 是 | 可选 | 否 | 否 | 是 | v1.1 候选 |

说明：

- `Edit` 只应继续服务文本类内容。
- 非文本类型的第一目标是“看见、理解、决定下一步”，不是修改。
- `Search` 对大文件或结构化文件要按成本分级，不要求所有类型第一版都支持。

## v1.1 候选类型排序

### P0：先做

1. 压缩包内容预览

价值：

- Finder 和 Quick Look 对压缩包内部结构的临时查看不够顺手
- 用户经常只想知道里面有什么，而不是立刻解压

首版范围：

- 展示文件平铺列表
- 展示文件数量与顶层目录数量
- 首版只承诺系统工具能稳定列目录的容器或 tar 组合包：`.zip`、`.tar`、`.tgz`、`.tbz2`、`.txz`、`.tar.gz`、`.tar.bz2`、`.tar.xz`
- 支持外部打开或解压到系统默认流程

不做：

- 内嵌编辑压缩包
- 复杂解压管理器
- 密码压缩包破解或管理
- 普通 `.gz`、`.bz2`、`.xz` 单文件压缩流和 `.7z` 首版不承诺预览

2. SQLite / 数据库文件轻预览

价值：

- 用户常常只想快速确认有哪些表、字段和少量样本数据
- 打开完整数据库工具太重

首版范围：

- 展示表列表
- 展示 schema
- 展示每张表前若干行样本
- 支持外部打开

不做：

- SQL 编辑器
- 写入数据库
- 索引分析、查询优化、迁移管理

3. 更多开发与数据文本格式

价值：

- 这些文件本质可读，但经常因为后缀或编码导致系统预览体验不稳定

首版范围：

- 扩展常见纯文本后缀白名单
- 继续保持“已知格式优先，二进制检测兜底”
- 支持语法高亮或纯文本兜底

不做：

- 为每个小众格式定制复杂渲染

### P1：随后做

1. EPUB 预览

价值：

- 用户可能只想确认电子书内容、目录、元数据

首版范围：

- 展示标题、作者、目录
- 展示正文前若干章节
- 支持搜索目录或当前文本

不做：

- 完整阅读器
- 书库管理
- 批注、书签、同步

2. 常见二进制开发产物元数据预览

价值：

- 用户经常需要确认文件是什么、大小、架构、版本或基本信息

首版范围：

- 展示文件类型、大小、创建修改时间
- 对可识别类型展示基础结构信息
- 支持外部打开

不做：

- 反编译
- 深度分析器
- 安全扫描器

## 流程可靠性要求

v1.1 的体验质量应该按连续使用场景验证，而不是只验证单次打开。

### 打开

- 快捷键触发后窗口应立即出现
- 文件定位、分类、读取和渲染继续异步进行
- 文件类型不可预览时，应展示清晰的兜底卡片，而不是静默失败

### 切换

- 在 Finder 连续切换文件时，旧文件状态必须完整复位
- Loading、错误、预览内容和工具栏状态不能串到下一个文件
- 大文件或重型类型切换时，应优先保持窗口响应

### 关闭

- 关闭后应可靠回到 Finder 流程
- 焦点回归、窗口飞回和资源释放不能互相打架
- 关闭中的异步任务不能污染下一次打开

### 失败兜底

- 不支持的类型应优先展示元数据和“用默认应用打开”
- 读取失败要说明失败原因
- 权限缺失要引导用户回到已有 Onboarding / 权限流程

## 不做范围

v1.1 不做：

- 深度编辑器能力
- 项目级文件管理
- 多窗口工作区
- 复杂插件系统
- 对所有文件类型的完整功能平权
- 非文本类型的写入修改

## 成功标准

v1.1 成功时，用户应该形成这样的感受：

`我不知道这个文件系统能不能预览，但我可以先用 QuickCookies 看一眼。`

可观察信号：

- QuickCookies 覆盖更多系统默认不舒服的临时查看场景
- 连续查看多个文件时状态稳定、焦点稳定、反馈稳定
- 用户能理解哪些类型可以编辑，哪些类型只是预览
- 不支持或失败时仍然有清楚下一步

## 实施前需要确认的问题

1. P0 候选里是否优先做压缩包、SQLite、更多文本格式这三类？
2. SQLite 首版是否允许依赖系统 `sqlite3` 命令或系统库读取？
3. 压缩包首版是否只支持系统工具能稳定列目录的格式？
4. 非文本类型是否统一不提供编辑入口？

## 推荐结论

v1.1 最适合做：

`更广的临时预览覆盖 + 更可靠的连续预览流程。`

这条路线既回应了 Quick Look 格式支持不足的问题，也守住了 QuickCookies 的轻量定位。
